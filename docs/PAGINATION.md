# Layout Engine — ページ割付と動的コンテンツ

状態: アルゴリズムドラフト。LAYOUT_MODELとPUBLICATION_RENDERINGを参照。

## 1. 割付の流れ

1. 入力・参照・部品ツリー・番号区間・面の妥当性を検証。
2. 既知の紙面・固定予約領域を計算。意味的番号/見出し等は入力済み。
3. セクション境界とブロック境界に開始制約を集約。先頭のみcontinuous抑制を適用。
4. 予定ページの利用可能幅/高さで計測。制約を満たす割付候補から決定的に選択。
5. 断片を追加し、必要なら次ページへ。各操作に理由を記録。
6. 脚注・ページ依存値・反復条件・目次を解決し、必要時再組版。
7. 全体の内容・番号・面・範囲・収束を検査してPagePlanを返す。

## 2. 境界制約

境界は開始必須か、面が指定されるか、分割/連結が可能かを分けて処理する。
- 構造: 固定ページ/固定見開き、番号区間、明示空白は維持。
- 明示pagebreakと明示sectionの面指定が矛盾したらエラー。anyは面を制限しない。
- 明示条件と部品既定の競合は明示優先・診断。通常の既定pageとspread-startは合成できる。
- continuousは最初の描画対象の部品由来startPositionだけflowに置換。途中は通常。空行/コメント、空セクションは抑制を持ち越さない。固定面、明示改ページ、物理不足は維持。
- keepWithNext/PreviousとminFollowingSpaceは連結候補を構築するが明示境界を越えない。両立不能なら緩和を警告（strictを緩和しない）。
- 条件が満たされているページ先頭では再改ページなし。面調整空白は一度だけ生成。明示blankは絶対に再利用しない。

## 3. 分割

availableHeight = 本文高 - 予約領域（本文内の場合） - 使用済み高 - 現在必要な余白。ヘッダー領域と本文内予約を二重控除しない。ページ先頭/末尾のmargin抑制を断片ごとに評価。
allowは最も進む有効境界、avoidは全体が空の適切ページに収まるなら移動、収まらなければ警告付き安全分割。strictは空ページにも収まらなければエラー。固定Canvasは原則不可分。候補なしで収まらない内容は診断停止、無断縮小・欠落なし。
段落は行境界、既定孤立行2行（調整可）。コードは論理行を基本にし、折返し行の許容は計測能力と明示設定に従う。表は行を基本にし見出しを再描画、巨大セルの分割はPoCで判定。columnは子境界・子の断片、rowの横並び複数子の同期分割は未検証。stackはflow断片に装飾を追従させ、fragmentDecorationで各断片/先頭/末尾を決定。断片化の対応がない型はエンジン能力を明示し、安全な代替案をレビューする。

## 4. 動的内容と収束

見出し・図表の意味的番号は利用側、ページ依存参照・誌面番号・脚注配置・動的反復条件はEngine。脚注は本文上の参照を起点に予約する。参照が移動したら脚注も再配置。脚注が大きい場合の許容分割は別fixtureで検証、末尾注へ無断変更しない。初期は固定予約領域を優先し、ページ末条件による領域変動を制限する。
各反復の状態署名にページ境界、面、番号、脚注割付、予約寸法、生成目次の行/寸法を含める。同一署名の連続＝安定、非連続再出現＝循環。反復上限・ページ上限・実行取消・資源上限を設ける。上限数値はPoCで確定。未収束はエラー、部分計画は閲覧用のみ。
各配置ステップは未処理の原稿/断片の前進、有限の明示空白消費、一度の面調整、停止のいずれかを要求し、同じ条件で空ページを無限生成しない。

## 5. 試験

PG-01 既存ページ先頭のany、PG-02 左右競合、PG-03 continuous先頭/途中、PG-04 allow/avoid/strict、PG-05 長い段落/コード/表、PG-06 見出し＋本文連結、PG-07 固定見開き直前の面、PG-08 目次循環、PG-09 脚注の移動、PG-10 予約領域の競合、PG-11 取消と進捗なし検出。入力・断片位置・境界理由・診断を期待値として記録。全て未検証。
