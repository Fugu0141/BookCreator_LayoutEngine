# 数式の独立コンパイル・配置設計（UX-10h-8l）
Status: design, not an implemented renderer. MIT project license applies to original code and documents; third-party fonts/renderers retain their own terms.

## 目的と現状
数式原文の編集と組版済み数式の配置を分離し、通常本文の編集で未変更の数式を再解析・再組版しないことを目標とする。BCMの数式原文が正本。エディタの確定は原文トランザクションであり、画像の保存を必須にしない。編集中の数式もプレビュー可能で、失敗は診断、旧紙面は前回の結果と明示する。
現行は独自の制限付きTeX風パーサー → ネイティブMathMLであり、外部LaTeXプロセスは実行していない。browser-lines.tsのsnapshotRequest・appendStyled（折返し・凍結行検証・描画）とmath-preview.tsのmeasureDisplayMathで解析、要素生成、フォント準備・実測が反復する。インライン数式/装飾を含む行は現行均一テキストキャッシュ対象外。
BookCreator #143のLinux CI全冊21ページでは実測区間中央値351.1ms（無効）/417.6ms（温状態）。数式固有の時間は未計測なので、数式が支配的な原因とは断定しない。#33は行生成と読み取りの分離を実装済み。

## 境界
1. 原文・意味解析: BCMは安定ID、数式文字列、原稿範囲、参照・式番号を保持する。数式構文・意味表現はEngineに独立させる。GUIや特定原稿IDを必要としない。
2. 構文コンパイル: 記法の版・完全一致する原文・inline/displayの別をキーに検証済み不変ASTを生成。構文エラーを成功成果物として保持しない。既存の深さ・長さ・セル数等の入力制限はキャッシュ参照前にも適用する。
3. 数式組版: AST・数式フォント実体の版/環境・サイズ・display/scriptスタイル・描画器/計測方式の版から、独立した数式成果物を生成。幅・高さ・ベースライン（上/下の張り出し）を物理単位または定義した固定小数単位で記録。ink boundsとadvance boundsを区別。可変寸法のフォールバック、色の扱い、丸め誤差は検証する。通常はページ番号、原稿位置、式番号、周囲の本文、配置座標はキーに含めない。
4. 配置: インラインは分割不可の幅・高さ・ベースライン付きatomとして行送り/折返し・行高を計算。行全体は本文や幅が変われば再計測が必要。独立数式は自然寸法を利用し、ページ幅、中央配置、式番号の左右余白、溢れを別に評価する。式番号は参照解決・ラベル描画の値であり数式本体を再コンパイルしない。行列・aligned・長い式の改行方針は明示的な制約として扱い、幅依存成果物ならその制約もキーに含める。既存の厳格な溢れ拒否を維持する。
5. 描画: 成果物から各配置の独立したノードを生成する。DOMの移動・同一要素の共有は禁止。原稿参照範囲、アクセシブルな数式表現、式番号、検索/コピー・再編集を維持する。

## 成果物の候補と採用条件
- 第一段階: 不変AST/安全な生成済みMathMLテンプレートの再利用。MathMLは現在の表示・式対応を維持しやすいが、cloneしてもブラウザー内部のレイアウトは発生する。これだけで完成とはしない。
- 第二段階: 数式単体の自然寸法と基線を計測し、型付き配置用atomとして独立させる。幅や基線が異なる文脈との一致を実ブラウザーで検証する。生のDOMや任意HTMLを永続キャッシュにしない。
- 第三段階: SVG/ベクター命令の候補を比較する。MathMLから忠実にSVG変換できると仮定しない。既存のベクター数式描画技術も候補とし、サポートする構文・フォント・組版精度・依存ライセンス・オフライン動作・起動時間・描画性能・PDF出力を比較する。PNGはサムネイル等に限定し、印刷用の既定方式にしない。ベクター化の場合も意味情報を別途保持。外部URL、script、foreignObject等を任意入力から許可しない。独自数式描画器の全面実装は測定と候補比較を経て判断する。
- プレビューと出版時で同じ成果物の幾何契約を利用する。PDFで実際にベクター出力されること、フォントの埋込/サブセットの権利、数式の可読性は別途確認。未達の間はpublicationReady=falseのまま。

## キャッシュと安全
書籍セッション/描画環境に属する明示所有のキャッシュを用いる。AST・ベクター・寸法の各容量はエントリ数、原文コード単位、ノード/命令数、推定バイト数等で上限を設ける。上限値は試験で決め、無制限に保持しない。LRU・世代番号により書籍切替、フォント登録/変更、DPR・ブラウザー環境変化、描画器版更新時の失効を行う。フォントによらないASTは描画環境の変化で再解析不要だが、書籍切替時は解放。旧世代の遅延処理は新世代に書き戻さない。原文や成果物のクラウド送信・永続化は初期範囲外。画像素材とは別の内部生成物扱い。編集時の未確定原文を正本へ暗黙保存しない。

## 実装順と計測
A. #33の本体接続・同一fixtureで性能再測定。その上で数式の解析、要素生成、フォント準備/検証、実測の回数と時間を個別に測る。本文だけ、数式多数、混在、変更1個、フォント切替、本文幅変更、式番号変更を比較。計測には数式本文や識別子を含めない。
B. 解析・MathML生成の責務分離、不変ASTの有界キャッシュ。パーサー互換性、入力拒否、キャッシュ有効/無効でAST・MathML一致、独立ノード生成、失効・容量・取消を確認。
C. 数式単体の寸法・基線・ink boundsの再利用PoC。独立数式から始め、次にインラインへ。番号・幅・本文の変更で不要な数式組版が再実行されないことをカウンターで検証。現行MathMLとのページ境界・原稿対応・描画・溢れを比較。
D. 必要ならSVG/ベクター方式を候補比較し、Aの測定を同条件で再実行。式の変更1個でコンパイルミス1個を目標（同一描画条件・キャッシュ容量内）。キャッシュ追い出し、フォント変更、幅依存式では再生成を許容。速度・メモリ・PDF品質を確認して採用可否を決定。
E. 原稿の変更範囲を引き継ぐ増分組版、分割実測、必要ページ描画へ接続。128ブロックなどの既存上限を単に緩めない。Windows実機で確認する。

## 非目標
完全なLaTeX互換、任意マクロ実行、毎回外部LaTeXプロセス起動、画像を数式原文の代わりにすること、キャッシュのみで全ページ組版の費用がゼロになるという主張。速度向上量・最終描画方式は未確定。


## 計測基盤 A-1（UX-10h-8n）

Chromium smokeに12種類の固定合成数式を使う初期比較を追加。数式なし/インライン/独立数式/混在を各12ブロックで構成し、事前に各経路を1回実行した後、3回の正順/逆順比較を行う。混在の同一DOM一致、本文1箇所・数式1個・幅・式番号の変更が紙面に反映されることも確認する。出力は `MATH_BENCH` version 1（合成fixtureのラベル、直接API呼出数、経過ms、ブロック/数式/ページ件数と既存の段階別数値のみ）。
解析API単独、MathML生成API（解析込み）、フォント準備・ネイティブ検証API、独立数式実測API（解析・生成・フォント検証を含む）を個別に反復する。これは重複を含む独立したマイクロベンチマークであり、合算や差引きによって厳密な内部時間を求めない。callsは明示したAPI呼出数で、全冊組版内部で発生した解析/生成回数ではない。数式固有の本番経路カウンターは次段階。
今回は既定auto数式フォント・単一Chromiumセッション・キャッシュ未指定の基準値。登録フォント切替時の正しさは既存テスト、性能比較は後続。fixture以外の原稿を使用せず、数値に原文/パスは含めない。速度閾値は設定せず、出力の完全性、変更反映、測定値の妥当性、計測ホストの解放を検証する。CI・性能値は未確認。


## 構文コンパイラ・キャッシュ B-1（UX-10h-8o）

- BookCreator #144は全5CI成功・統合済み。同じfixtureの21ページ比較で無効/温状態の壁時計中央値382.5/457.85ms、実測305.95/376.4ms。#143の444.5/522.0msと比べ短縮を観測したが、別CI実行であり厳密な同時対照比較ではない。
- #35は全2CI成功・統合済み。12個の合成数式の中央値は解析単独0.1ms、inline MathML生成（解析込）0.3ms、フォント準備1.8ms、独立数式実測（重複込）6.8ms。紙面全体の本文のみ5.1ms、inline14.9ms、display7.4ms、混在10.9ms。小規模なautoフォントfixtureであり、各プローブは重複する。構文解析のみが支配的とは判断しない。
- `createMathCompilationCache()` はホストが明示所有するキャッシュ。exact sourceとinline/blockをキーに、既存パーサーの成功ASTだけを再帰freezeし内部保持する。フォント、幅、配置、番号、DOM、原稿位置に依存しない。512件/100,000 UTF-16コード単位/50,000 ASTノードのLRU上限、数値のstats、clearを提供する。公開のparse関数は従来の独立ASTを返す。外部ASTや任意HTMLを受け付けない。
- `createPlainTextPagePreview({mathCache})` のオプションから、スナップショット検証、名前付きスロット、hard-line分割、inline描画、独立数式、凍結行描画に明示的に渡す。描画関数は内部ASTを受け、毎回新しいMathMLを作る。入力制限、原文範囲、フォント準備、寸法検証は維持。未指定時は従来通り。キャッシュは構文だけで、数式の実測やブラウザの内部レイアウトを省かない。
- キャッシュへの書き込みは同期的なコンパイル時のみ。ホスト接続時は書籍切替/取消時に古いキャッシュをclearし、新しいインスタンスに置換すること（旧非同期ジョブが旧インスタンスを再利用する可能性があるため）。フォント変更だけでは構文キャッシュを失効させる必要はない。永続化・外部送信なし。
- 単体検査2件とChromium回帰を追加。構文モードと不正入力、LRU/上限/消去、キャッシュ有無のplan/slices/DOM一致、本文/幅/番号の変更によるミス増加なし、式1個変更でミス1件、DOMの独立性を検証する。CI・Desktop接続・数式自然寸法の成果物化・実機性能は未確認。


## 独立数式の自然寸法候補 C-1（UX-10h-8p）

- #36は全2CI成功・main統合済み。次の段階として `createDisplayMathGeometryCache(document)` をオプトイン追加。数式原文・数式フォント・物理フォントサイズをキーとし、独立数式の自然な幅・高さ（CSS px）だけを保持する。式番号・利用可能幅・原稿位置はキーに含めない。512件/100,000 UTF-16コード単位のLRU。構文キャッシュとは独立。DOMやcaller-ownedデータを保存しない。
- 文書所有、FontFaceの同一性/記述子/ロード状態、FontFaceSetの状態、DPRの変化で失効。clearまたは環境失効後に古い非同期処理が結果を書き戻さないようepochを確認。システムフォント等のFontFaceSet外の変更はホストからclear/新規インスタンスへの置換が必要。
- 再利用時はfonts.readyを待ち、保存済み寸法を番号の左右余白・高さの配置候補に用い、反復する数式フォントのネイティブ能力probeを省く。現在のMathML要素の幅・高さは実際に確認し、候補と厳密一致かつ既存の溢れ・ラベル幾何検査に合格した場合のみ採用。不一致/候補による拒否時は破棄して従来の全実測・検証に戻る。現段階はネイティブMathMLレイアウトそのものを省略しない。数式固有のベースライン計測、inlineのatomic box、SVG化は未実装。
- `createPlainTextPagePreview({displayMathCache})` から独立数式、部品のhard-line数式に伝播。未指定時は従来と同じ経路。新規の値・候補は出版確定を許可しない。statsのhits/misses/fallbacksは数式寸法候補の採用/全実測/候補失敗を記録する。
- ブラウザー検査で異なる式番号/幅、式変更、サイズ変更、実際のoverflow拒否、非共有DOM、plan/slices/DOM一致、別文書拒否、FontFaceSet追加削除、clearとホスト解放を確認する。CI・性能改善値・Desktop接続は未確認。


## インライン数式の自然寸法・基線 C-2（UX-10h-8q）

- #37は全2CI成功・main統合済み。独立数式に続き、`measureInlineMathGeometry(document,source,fontSize,family,mathCache,geometryCache)` を追加する。実際のインライン数式と同じspan/MathMLを隔離した計測DOMに配置し、幅・高さと隣接するゼロ寸法のbaselineマーカーから上端基準のベースラインを取得する。値はCSS pxの不変レコード、publicationReady=false。文字の基線・上下の張り出しを保った将来のatomic box化に用いる候補。
- `createInlineMathAtom` で計測用spanと既存紙面のspan生成を共通化。原稿範囲は紙面側で付与する。生DOMの共有や保存はしない。既存の行割付・凍結行実測は変更しない。
- `createInlineMathGeometryCache(document)` は独立数式の寸法キャッシュとは別の所有オブジェクト。原文・サイズ・数式フォント別に512件/100,000 UTF-16コード単位のLRU、FontFaceSet/記述子/状態/DPR変更時の失効、文書所有、epoch、clearを共有する。キャッシュヒットでは数値だけを返し、隔離DOM生成や能力probeを行わない。元の数式解析上限は維持し、不正な入力・計測失敗は保存しない。FontFaceSet外の環境変更はホストからの失効が必要。
- Chromiumで4種類の数式の寸法/基線を本文のフォント・行高・幅が異なる2つの実行コンテキストと比較し、許容差0.125 CSS px以内を検査する。キャッシュ有無の値、サイズ変更、不正入力、別文書拒否、フォント環境失効、clear、DOM解放も検証する。
- 今回は候補APIの独立したPoC。通常の紙面生成に固定寸法のboxを代入する変更は行わないため、本番のインライン数式の再レイアウトは省略されない。実際の折返し位置・行高・原稿範囲・PDFの印刷品質と互換性を検証した上で次段階で接続する。任意のフォント/文脈での等価性、CI、性能改善値、Windows実機は未確認。


## 固定インライン部品による折返し C-3（UX-10h-8r）

- #38は全2CI成功・main統合済み。`createPlainTextPagePreview({inlineMathCache})` および `measurePlainTextLines` に明示的なオプトインを追加。検証済みインライン数式ごとの幅・高さ・基線の候補を取得し、折返し用DOMではMathMLを作らず空のinline-block（固定幅・高さ、下降分のvertical-align）に置換する。候補は内部生成値のみ、原稿のatom範囲・本文スタイル・分割禁止を維持。
- 凍結行は元のネイティブMathMLを構築しフォント能力を検証する。実測座標と行高を固定候補の折返し結果に対し0.125 CSS pxの厳格な許容差で比較し、従来の溢れ・範囲・ink検査も維持。候補処理が失敗した場合は計測ホストを解放し、従来のネイティブ折返し・行検証を独立にやり直す。紙面描画は従来のMathMLのまま、空の部品は残らない。
- multilineのhard-line分割、部品のprimary/named slotにも明示的なキャッシュが伝播する。独立数式行は従来のdisplayMathCache経路。キャッシュ未指定では従来経路を維持。statsに候補採用段落数placementsとネイティブ再試行数placementFallbacksを追加。clearで双方を初期化する。
- Chromium回帰で複数行/ページの行範囲・高さ・plan/slices/紙面DOMの一致、実際の採用数、本文/幅編集時の候補再利用、式1個の変更時の新規候補1件、過大数式の拒否、ホスト解放を検査する。
- 現段階は実験的オプトイン。候補取得・環境検査の費用、未対応文脈でのfallback、凍結行と紙面のネイティブ描画費用が残る。CI、性能改善値、登録フォント全般、Windows実機、Desktop接続、出版品質、SVG等の代替描画方式は未確認。既存の入力上限を緩めない。
